⚙️ CONFIGURACIÓN BIND9 - EXPLICACIÓN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

directory "/var/cache/bind"
  → Ubicación del caché y archivos de zona de BIND9

recursion yes
  → Permite que BIND9 resuelva nombres recursivamente
  → Es decir, puede consultar otros DNS si no tiene la respuesta

allow-recursion { localhost; 10.26.1NN.0/24; 10.26.2NN.0/24; }
  → Define QUIÉN puede hacer consultas recursivas
  → localhost: La misma instancia
  → 10.26.1NN.0/24: Instancias en Subred Ubuntu
  → 10.26.2NN.0/24: Instancias en Subred Windows
  → ⚠️ Esto evita que Internet use tu DNS (seguridad)

dnssec-validation auto
  → Valida automáticamente firmas DNSSEC
  → Proporciona seguridad en resolución DNS

listen-on { any; }
  → Escucha en todas las direcciones IPv4

listen-on-v6 { any; }
  → Escucha en todas las direcciones IPv6


📋 VERIFICACIÓN POST-DEPLOYMENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Conectar a Ubuntu:
   ssh -i vockey.pem ubuntu@<ELASTIC_IP>

2. Verificar archivo existe:
   cat /etc/bind/named.conf.options

3. Verificar BIND9 corriendo:
   sudo systemctl status bind9

4. Verificar puerto 53:
   sudo netstat -tlnp | grep :53
   
   Debería mostrar:
   tcp   0  0 0.0.0.0:53   0.0.0.0:*   LISTEN    PID/named
   tcp6  0  0 :::53        :::*        LISTEN    PID/named

5. Probar resolución DNS (desde otra instancia):
   nslookup google.com 10.26.101.100
   dig @10.26.101.100 example.com

6. Ver logs:
   sudo tail -20 /var/log/syslog | grep named


🔧 MODIFICAR CONFIGURACIÓN POST-DEPLOYMENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Si necesitas cambiar la configuración DESPUÉS de desplegar:

1. Editar archivo:
   sudo nano /etc/bind/named.conf.options

2. Validar sintaxis:
   sudo named-checkconf /etc/bind/named.conf.options
   
   ✓ Si no muestra error, está bien

3. Reiniciar BIND9:
   sudo systemctl restart bind9

4. Verificar:
   sudo systemctl status bind9


💡 OPCIONES ADICIONALES (Comentadas)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Forwarders (DNS públicos):

Por defecto DESHABILITADOS (comentados):
//forwarders {
//    8.8.8.8;      ← Google DNS
//    1.1.1.1;      ← Cloudflare DNS
//};

Para HABILITAR forwarding:
1. Descomenta las líneas (elimina //)
2. Edita el archivo: sudo nano /etc/bind/named.conf.options
3. Reinicia BIND9: sudo systemctl restart bind9

Con forwarders habilitados:
- Si BIND9 no tiene respuesta local
- Consulta a Google DNS (8.8.8.8) o Cloudflare (1.1.1.1)
- Retorna la respuesta al cliente
